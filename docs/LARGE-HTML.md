# 大 HTML 支持契约

状态：2026-10-19 架构优化；放弃要求绑定信用卡激活的 R2 存储，全面切换为 **Cloudflare Workers KV**（纯免费层、零绑信用卡、单 Value 允许 25 MiB）。两端本地大 HTML 回归与 WASM dry-run 均已全部通过。普通服务器场景继续使用本地文件存储。

## 范围与兼容

- 单个 HTML 正文的 UTF-8 字节数上限 10 MiB（10,485,760 字节）；text／markdown 保持 500 KiB。不支持任意二进制、分片上传或断点续传。
- 沿用创建 JSON、CLI、无标题、公开／Token ACL、期限、Cookie／Bearer 和 POST 阅后即焚契约。JSON 请求封装另限 16 MiB，防止大量转义或无关字段耗尽内存；封装超限也返回 413。
- 旧内容和不超过 500 KiB 的新内容继续内联数据库；大 HTML 使用私密存储：Worker 端使用 Workers KV（免费层、免信用卡），普通服务器使用数据库旁的私密 bodies 目录（`<数据库>.bodies/`）。正文不经公开静态文件路由分发。
- 新增 `content_bodies` 表记录 content_id、不可复用随机 object_key、UTF-8 字节数和 SHA-256；外键随内容删除级联。大正文在 contents.content 中存空串，读取依赖该明确引用，不能依据正文文本猜测外部存储。
- 新版要求先迁移 `0004_content_bodies.sql` 再发布；旧行不搬迁。SQLite 升级前备份；有外部文件后，备份必须同时包括数据库与 bodies 目录。回退旧应用前必须停止大文件写入并评估新内容可读性，不能盲目回滚。

## 写入、读取及失败

1. 先认证、校验输入／大小／TTL／ACL，再生成随机 ID，写入不可变正文（KV 或本地 bodies 目录）；随后同一数据库事务提交正文引用、内容元数据和 ACL。
2. 正文写失败不创建内容；数据库提交失败尝试删除已写正文，崩溃遗留由回收器处理。不以降级内联绕过 D1 行限制。客户端超时可能已经提交，不承诺自动重试幂等。
3. 先检查当前权限／期限／安全方法，再取正文；取回时校验长度、SHA-256 和 UTF-8。缺失或损坏为服务故障，不伪装成空正文，不泄露给未授权者。
   大正文公开页只返回固定大小的页面外壳，通过无凭证的同源正文 GET 加载并创建禁脚本 sandbox，不把最多 10 MiB HTML 再按属性转义嵌入服务端页面。这样避免引号密集正文多倍膨胀；加载失败在外壳内显示不可用，不把 HTTP 200 外壳当正文读取成功。小内联内容保持原渲染兼容。
4. burn 在可用正文已取回／校验后才执行原子条件删除；只有删除获胜者能把正文发给客户端，正文 POST 与下载 POST 共用此竞争。存储读取失败不得消费，Cookie GET／HEAD 和预取仍不得消费。交付中断仍可能已消费，保持原有 at-most-once 语义。
5. 元数据删除／消费先提交，撤销公开访问及 ACL，再尝试删正文。物理删除失败不恢复可访问性，由定时回收重试；不把已提交删除向客户端谎报为可安全重试的未执行操作。

## 回收与资源边界

- 小时任务先删除过期元数据／引用，再分页扫描专用 `bodies/` 前缀（KV 或本地私密目录），逐个核对引用，只删除无引用且创建已超过 1 小时的孤儿正文。1 小时宽限保护尚未完成提交的上传；正文 key 永不复用，禁止用户自定义 key 或访问文件路径。
- KV 写入时附带 `expiration`（到期时间戳），KV 平台层自动具备到期淘汰能力，双重兜底。
- 每次扫描按页处理，不一次加载所有对象正文；存储／数据库故障保留对象，不依据失败查询认定孤儿。仅记录通用故障信息，不记录上传正文或 Token。
- 大文件正文响应及渲染仍有最多 10 MiB 的有界缓冲，并非无限文件流服务；保留 16 MiB 请求封装上限，需实际 Worker 构建与大文件测试，不凭配置宣称容量／负载验收。
- Workers KV 纯免费、免绑信用卡；绑定缺失时大文件写入失败，原有内联内容仍可用。

## 验收门禁

- 两端跑旧会话／核心 API／CLI 回归；新增 HTML 恰好 10 MiB 接受、多 1 字节拒绝，text／markdown 仍在旧边界拒绝；无 Content-Length 的请求也有封装上限。
- 验证公开预览／私有 ACL／原样下载、burn 预览与正文／下载竞争、对象缺失不消费、撤权／到期／删除立即不可访问、写失败回滚及孤儿回收。
- 验证旧库和旧正文升级不变、存储引用不含正文；KV 本地运行时与本地文件系统分别取证。
- 用户指定约 1.68 MiB 的 HTML 只用于隔离本地上传、预览和下载哈希比对，不上传到生产或公开服务；生产烟测只能使用合成 HTML。

依据：Cloudflare D1 [限制](https://developers.cloudflare.com/d1/platform/limits)（单值／单行 2,000,000 字节，L2）；Cloudflare Workers KV [限制与定价](https://developers.cloudflare.com/kv/platform/limits/)（单值上限 25 MiB，免费计划无需信用卡，L2，2026-10-19 核对）。本项目固定 worker crate 0.8.7 的类型定义为实际 Rust API 基准。

## 当前验证证据（L1）

- `tests/large-html.cjs` 在隔离 Axum／SQLite／文件存储和本地 Worker／D1／KV 上均通过：10 MiB 接受、多 1 字节拒绝，16 MiB 请求封装拒绝；元数据中正文为空、有长度与哈希引用；公开／私有、原样下载、BOM／CRLF、burn 正文／下载竞争、对象缺失不消费、对象缺失时非 burn POST 先返回 400、真实 CLI 均通过。Worker dry-run 通过。
- 用户样例 1,763,146 字节，在两端分别通过真实 Chrome 文件选择导入、私有隔离预览、原样下载 SHA-256 比对；没有上传到生产。样例测试页面阻断非 loopback 网络请求。
- 27 项 Rust 测试、4 项 CLI 单测通过。两端 Clippy 0 警告，WASM 构建与 dry-run 均顺利通过。
- 普通服务器场景（Axum + SQLite + bodies 目录）继续完整支持，双端构建与运行均保持绿灯。
